# Shared Hosting Deployment

> The complete deployable application is in **`htdocs/`**. Upload its *contents*
> to a conventional PHP/MySQL host, set the database values in `.env`, import
> `database/install.sql`, and open the site. No Node.js, Python, Docker,
> Composer, external API, CDN, WebSocket or background worker is required at
> runtime.
>
> **Virtual credits only.** There is no deposit, withdrawal, payment or crypto
> code, and therefore nothing of that kind to configure.

`htdocs/` is generated by `tools/build_htdocs.php`; do not edit it in place.
Change the source tree and rebuild:

```bash
PATH="$HOME/bin:$PATH" php tools/build_htdocs.php
```

The build refuses to delete a directory it did not create (it looks for
`.htdocs-build`) and preserves an existing `htdocs/.env`.

---

## 1. Requirements

| Requirement | Minimum | Notes |
| --- | --- | --- |
| PHP | 8.3 | `composer.json` requires `>=8.3`; typed properties, enums and `readonly` are used |
| PHP extensions | `pdo_mysql`, `json`, `mbstring` | `openssl` recommended; Argon2id optional (bcrypt fallback) |
| Database | MySQL 8.0+ or MariaDB 10.6+ | InnoDB, `utf8mb4`, JSON columns, `CHECK` constraints |
| Web server | Apache 2.4 + `mod_rewrite`, or LiteSpeed | Nginx configuration is given below |
| TLS | strongly recommended | bearer tokens over HTTP are disclosed tokens |
| Disk | ≈ 3 MB application + database | no build step on the host |

`pdo_mysql` is the only database driver used in production. There is no Redis,
memcached, queue, cron requirement or writable upload directory.

### What the host does *not* need

* Composer — the production autoloader is already in `htdocs/vendor/`.
* Node.js/npm — the frontend is plain ES modules and CSS, no build.
* Python, Docker, Firebase, Supabase or any external service.
* Node/PHP background daemons or WebSockets — every request is self-contained.
* Outbound HTTP access — no runtime call leaves the server.

The only runtime package is `psr/log`. Development tools (PHPUnit, PHPStan,
PHP_CodeSniffer, Playwright) are not in `htdocs/`.

## 2. Directory layout

```
htdocs/                      <-- upload the CONTENTS of this directory
├── index.php                front controller: API + SPA shell
├── app.html                 single-page application shell
├── assets/                  CSS, ES modules, SVG artwork (served directly)
├── src/                     PHP engine, games, API, CLI commands   [private]
├── config/app.php           defaults; overridden by .env          [private]
├── database/
│   ├── install.sql          complete fresh-database schema
│   └── migrations/*.sql     incremental migrations                [private]
├── vendor/                  psr/log + production Composer autoload [private]
├── bin/console              CLI (migrate, users, purge)           [private]
├── storage/logs|cache/      only writable paths                   [private]
├── .htaccess                routing, security headers, caching
├── .env.example             copy to .env and fill in
└── README.md                short operator quickstart             [private]
```

Every private directory has its own `.htaccess` denying HTTP access. The root
`.htaccess` denies dotfiles, `.env`, SQL, Markdown, logs and configuration
files, and rewrites application routes to `index.php`. `index.php` also refuses
those paths when run under PHP's built-in server.

**The application must be installed at a domain root or its own subdomain.**
The SPA uses root-relative routes (`/slots/...`, `/api/v1`, `/assets/...`);
uploading it to `example.com/casino/` will break routing and assets. Use a
subdomain such as `casino.example.com` instead.

## 3. Install

1. **Create the database.** In cPanel/Plesk, create a MySQL database and a user
   with all privileges on that database. Note the host (usually `localhost`),
   database name, user name and password.
2. **Upload.** Upload the *contents* of `htdocs/` into `public_html/` (or the
   subdomain root), preserving directories.
3. **Configure.** Copy `.env.example` to `.env` and set at least:

   | Variable | Example |
   | --- | --- |
   | `APP_ENV` | `production` |
   | `APP_DEBUG` | `false` |
   | `APP_URL` | `https://casino.example.com` |
   | `DB_HOST` | `localhost` |
   | `DB_PORT` | `3306` |
   | `DB_DATABASE` | `account_casino` |
   | `DB_USERNAME` | `account_engine` |
   | `DB_PASSWORD` | the database password |

   Keep `DB_CHARSET=utf8mb4` and `DB_COLLATION=utf8mb4_unicode_ci`. Leave
   `PASSWORD_ALGO=argon2id`; the engine automatically uses bcrypt if the host's
   PHP build has no Argon2 support, and records that per user.
4. **Import the schema.** In phpMyAdmin select the database → **Import** →
   `database/install.sql` → Go. This creates 19 tables and records all five
   migrations, so the runtime reports the schema as current. Import once into
   an empty database.
5. **Permissions.** `storage/` must be writable by PHP:
   `chmod -R 775 storage`. On hosts running PHP as a different user, set
   ownership accordingly or use `777` only on `storage/logs` and
   `storage/cache` if the host requires it. Nothing else needs write access.
6. **Visit the site.** Register a player. The lobby is public; opening a game
   requires an account.

### Alternative schema import (SSH)

If the host provides a terminal, `php bin/console db:migrate` applies the same
migrations from `database/migrations/` and records the ledger itself. Use one
method or the other, not both. `php bin/console db:status` must then print
`No drift detected.`

### First administrator

Register a normal account in the browser, then either:

```bash
php bin/console user:admin --username=your_username
```

or, without SSH, in phpMyAdmin:

```sql
UPDATE users SET role = 'admin' WHERE username = 'your_username';
```

The Admin entry then appears in the account drawer. The role is read from the
database on every request; no client value can grant it.

### Health check

```bash
curl -sS https://casino.example.com/api/v1/health
```

Expected shape: `{"ok":true,"data":{"status":"ok",...},"error":null,"meta":{}}`.
Also request `/api/v1/games/lobby`; it must return 22 games.

## 4. Configuration reference

Configuration precedence: real environment variables → `.env` → defaults in
`config/app.php`. Only names on the explicit map in
`Core\Config\Config::withEnvironmentOverride()` have any effect.

| Variable | Production value | Purpose |
| --- | --- | --- |
| `APP_ENV` | `production` | environment label; seeded RNG refused outside dev/test |
| `APP_DEBUG` | `false` | never expose debug detail |
| `APP_URL` | public HTTPS URL | descriptive/base URL |
| `APP_TIMEZONE` | `Asia/Manila` | display/default timezone |
| `LOG_LEVEL` | `warning` | `debug` is noisy in production |
| `LOG_CHANNEL` | `file` | or `stdout` / `null` |
| `DB_*` | host values | PDO MySQL connection |
| `PASSWORD_ALGO` | `argon2id` | bcrypt fallback is automatic |
| `API_TOKEN_TTL_SECONDS` | `86400` | bearer-token lifetime |
| `API_RATE_LIMIT_PER_MINUTE` | `120` | database-backed rate limit |
| `ALLOW_SELF_REGISTRATION` | `true`/`false` | close public sign-ups if desired |
| `REGISTRATION_STARTING_BALANCE_MINOR` | `100000` | ₱1,000 virtual starting credit |

`.env` is gitignored and denied over HTTP. Never commit it, and never put the
database password in `config/app.php`.

## 5. Optional cron maintenance

None of these is needed for correctness; each keeps a table small. Use the
host's cron panel with the absolute path to the deployed console:

```cron
17 3 * * *  php /home/account/public_html/bin/console token:purge
27 3 * * *  php /home/account/public_html/bin/console session:expire
37 3 * * *  php /home/account/public_html/bin/console idempotency:purge
47 3 * * *  php /home/account/public_html/bin/console rate-limit:purge
57 3 * * *  php /home/account/public_html/bin/console audit:purge
```

Retention windows come from `AUDIT_RETENTION_DAYS` and
`RATE_LIMIT_RETENTION_DAYS`. If no cron is available, the tables grow but the
application keeps working.

## 6. Nginx equivalent

Apache and LiteSpeed use the shipped `.htaccess`. On Nginx:

```nginx
root /var/www/aurum/htdocs;
index index.php;

location / {
    try_files $uri $uri/ /index.php?$query_string;
}

location ~ \.php$ {
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_param HTTP_AUTHORIZATION $http_authorization;
    fastcgi_pass unix:/run/php/php8.3-fpm.sock;
}

# Private paths: Nginx does not read .htaccess.
location ~ ^/(src|config|database|vendor|storage|bin)/ { deny all; }
location ~ /\. { deny all; }
location ~* \.(env|sql|md|log|ini|lock|json|dist|neon|sh|bak)$ { deny all; }

add_header X-Content-Type-Options nosniff always;
add_header Referrer-Policy no-referrer always;
add_header X-Frame-Options DENY always;
add_header Content-Security-Policy "default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'" always;
```

Do not expose `src/`, `config/`, `database/`, `vendor/`, `storage/` or `bin/`.

## 7. Upgrades

Because `htdocs/` is generated:

1. Back up the database and the server's `.env`.
2. Build a new `htdocs/` locally from the new revision.
3. Upload the new files, keeping the server's `.env`.
4. Apply any new migrations with `php bin/console db:migrate`, then
   `php bin/console db:status` (must report no drift).
5. Clear the browser cache if the asset filenames changed.

The migration runner records a SHA-256 checksum per file and reports drift if
an already-applied migration changed. Never edit a migration after applying it.

## 8. Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Blank page / HTTP 500 | parse error, PHP version below 8.3, or unwritable log | check the host error log; run `php -l`; raise PHP version |
| 403 on every route | `mod_rewrite` unavailable (`.htaccess` fails closed) | enable `mod_rewrite`, or apply the Nginx rules |
| 404 on `/api/v1/...` | rewrite not active | same as above; confirm `.htaccess` was uploaded |
| CSS/JS 404 | uploaded into a subdirectory, or `assets/` missing | install at the domain root; re-upload `assets/` |
| “Could not connect to the database” | wrong `.env` values or DB user lacks privileges | recheck host/name/user; grant privileges on that schema |
| Login works, games fail | schema incomplete | re-import `install.sql` into an empty DB, or run `db:migrate` |
| “Dependencies are not installed” | `htdocs/vendor/` missing | re-upload the build; do not run Composer on the host |
| Admin menu missing | account is not an admin | grant `role='admin'` (see above) |
| Changes not visible | browser cache / old files | hard refresh; verify file timestamps |

## 9. Security checklist

* `APP_ENV=production`, `APP_DEBUG=false`, HTTPS enabled.
* `.env` exists on disk, is not in Git, and is not downloadable.
* `https://site/src/Core/Bootstrap.php`, `/config/app.php`,
  `/database/install.sql`, `/vendor/autoload.php`, `/.env` all return 403/404.
* `storage/` writable, everything else read-only to the web user.
* Database user limited to this schema.
* No test tooling, source exports, screenshots or documentation in the web root.
* Cron (if used) runs as a user that can connect to the database.

Details and residual risks: [PRODUCTION_SECURITY.md](PRODUCTION_SECURITY.md) and
[the backend security audit](../backend/SECURITY_AUDIT.md).

## 10. What was actually verified here

Verified locally against the generated `htdocs/` tree:

* PHP 8.3 built-in server as the production entry point, fresh MariaDB 10.11
  database imported from `database/install.sql` (19 tables, five migrations,
  no drift).
* `/`, `/assets/css/app.css` and `/api/v1/games/lobby` returned 200 with the
  correct content types; 22 games listed.
* Registration (201), login, token-authenticated `/auth/me` (200), both
  Argon2id and bcrypt hashing.
* Real mobile and desktop Chromium flows against the production tree: login,
  slot spin, blackjack deal, roulette spin, coin flip and search, with five
  settled rounds recorded in the production database and no console errors.
* Direct requests for source, config, SQL, vendor, logs, `.env`, README and
  `bin/console` returned 404.
* A copy of `htdocs/` moved to `/tmp` and served there worked identically,
  proving there is no dependency on the surrounding repository.

**Not verified here:** real Apache/LiteSpeed rewrite behaviour, a live shared
host's PHP configuration, HTTPS, and email (the app sends none). The
`.htaccess` rules and Nginx equivalent follow standard directives but were not
executed by Apache in this environment.
